JOIN ABSTRACTION DESIGN REVIEW

Scope: design guidance based on the supplied revised paper and legacy models.
This note is not a claim that the revised protocol has already been verified.

1. Defect in the legacy abstraction

Legacy N=2 mkstar(joined1, joined2, rho1, rho2), and N=3
mkstar3(joined123, rho1, rho2, rho3), retain all source policies. Distinct
input histories therefore yield distinct terms even when their effective
constraints are identical. The old ablation additionally uses mkstar2 for
partial views, making its binary/ternary outputs unequal by construction.
This does not implement the paper's idempotent, componentwise policy join.

2. Minimal replacement

Retain the existing roles, per-peer collection, and event/query names. Replace
only the policy payload algebra and join computation needed to represent the
checks in the paper. Each policy has one fixed, canonically ordered slot per
configured entity. A slot stores the effective constraint components. The
consensus stores the resulting slots only, with no original rho values,
arrival order, source-policy list, or number of contributing policies.

Self identifies the origin of an input policy and remains hash-bound there.
It is not joined as a constraint requiring all Self values to be equal and
does not become an input-history field in the consensus.

Within each model, all joins (including any partial-input diagnostic) must
use the same fixed entity schema. Do not change the output constructor arity
when omitting a contribution. Omitting a redundant contribution must be able
to leave exactly the same consensus term.

3. Component domains and operations

MRENCLAVE, MRSIGNER, ISVPRODID:
  Separate typed wildcard/exact constraints are easiest to audit.
  Any join x = x; equal exact values join to themselves; distinct exact
  values have no reduction, so a let evaluating that join stops the role.
  Exact atoms may remain symbolic (not enumerated). This is still a small
  algebra; finite SVN and TCB domains need not force arbitrary exact values
  into a finite enumeration. If claiming a completely finite policy domain,
  validate every exact value against an explicit finite list instead.

SVN:
  Use three ordered representative levels, 0 < 1 < 2. A requirement is a
  lower bound and join takes max. Evidence at level v satisfies bound r iff
  v >= r. Use only one canonical weakest bound: level 0 also denotes Any.
  Do not keep both Any and Min(0) as distinct normalized terms representing
  the same finite acceptance set. This proves only the finite ordered domain,
  not all SGX integer security-version values.

TCB:
  Use two acceptable appraisal outcomes, e.g. good and conditional, and
  three nonempty acceptance sets: {good}, {conditional}, {good,conditional}.
  Join is intersection. The two disjoint singletons conflict (no reduction).
  Explicit invalid/revoked statuses have no satisfaction rule for any set.
  These are symbolic categories, not a complete encoding of Intel status or
  collateral processing. Cryptographic collateral validation remains an
  explicit abstraction boundary.

Attester:
  For each instance, represent no contributed assignment or assign(P).
  Join is union of compatible assignments: none join x = x; identical
  assignments are idempotent; different assigned RPEs conflict.
  'none' does not authorize any attester: Stage 3 requires assign(currentRPE).
  If initialization validity already requires an assignment in every policy,
  omit none and retain equality-only join, documenting that restriction.

4. ProVerif 2.05 reduction syntax (same style as legacy joinid)

type meas.
type mpin.
const anyM: mpin [data].
fun exactM(meas): mpin [data].
fun joinM(mpin, mpin): mpin
reduc forall x: mpin; joinM(anyM, x) = x
otherwise forall x: mpin; joinM(x, anyM) = x
otherwise forall m: meas; joinM(exactM(m), exactM(m)) = exactM(m).

type vreq.
const min0, min1, min2: vreq [data].
fun joinV(vreq, vreq): vreq
reduc forall x: vreq; joinV(min0, x) = x
otherwise forall x: vreq; joinV(x, min0) = x
otherwise joinV(min1, min1) = min1
otherwise joinV(min1, min2) = min2
otherwise joinV(min2, min1) = min2
otherwise joinV(min2, min2) = min2.

type tcbset.
const allowGood, allowConditional, allowBoth: tcbset [data].
fun joinT(tcbset, tcbset): tcbset
reduc forall x: tcbset; joinT(allowBoth, x) = x
otherwise forall x: tcbset; joinT(x, allowBoth) = x
otherwise joinT(allowGood, allowGood) = allowGood
otherwise joinT(allowConditional, allowConditional) = allowConditional.

These are design snippets, not an independently executed test model. The
parent must parse the assembled definitions in the actual 2.05 environment.
If multi-constant declaration syntax is rejected, declare constants singly.

5. Avoid malformed typed inputs

ProVerif sorts do not by themselves restrict attacker inputs to the intended
constructors. Validate a chosen policy's shape and each finite-domain field
before producing PolicyDeclared / an Evidence Quote. In particular the
generic wildcard rules above return their other argument, so an arbitrary
name of type vreq/tcbset must not be accepted as a well-formed bound/set.
An equivalent implementation can enumerate the complete finite join table
so malformed operands fail, provided input initialization is also accurate.

6. Necessary checks for the algebra and the protocol

For every finite component, exhaustively check commutativity, idempotence,
associativity (with conflict as absorbing bottom), and that the accepted
outcomes of the join equal the intersection. Show at least one redundant
input example with exactly equal normalized policies, and one conflicting
exact/TCB/attester example that blocks before FullJoin. Repeat these in
ProVerif reachability diagnostics using the actual generated algebra; a
host-language truth table alone does not validate the emitted model.

The final model need not prove general semilattice theory. It must state
the finite abstraction, preserve real local joins over received policies,
and avoid relying on input-history injectivity to establish agreement.

7. Final implementation and executed validation

The preceding sections record the design review. The final shared algebra is
models/algebra.pvl; the illustrative declarations above are not its source.
The final implementation uses a shared symbolic attr sort for measurement,
signer, and product values, with separate fields in Req. Its SVN values are
V0/V1/V2. Its TCB symbols are Good/Outdated/Revoked/Invalid, with requirements
Both/OnlyGood/OnlyOutdated. Exact attr values and Assign(party) are symbolic;
only the explicit policy catalog and SVN/TCB components are finite domains.

Actual ProVerif 2.05 outputs were read from results/final-v2/:

  join-regression/output.log:
    20 queries; 16 raw true and 4 raw false, all as expected.
    Elapsed time for the entire model/query batch: 0.32 seconds.
    Parse and verification exit status: 0.

  join-specialization-regression/output.log:
    2 queries; both raw true, as expected.
    Elapsed time for the entire model/query batch: 0.10 seconds.
    Parse and verification exit status: 0.

These timings belong to the whole diagnostic model runs, not to individual
queries and not to the main Stage 2/3 protocol models.

For join-regression, the exact scalar count is:
  joinid 16 + joinv 9 + jointcb 9 + joinatt 16 = 50 join cases;
  matchid 12 + matchv 9 + matchtcb 12 + matchatt 12 = 45 match cases;
  total 95 scalar cases, plus 18 composite-entry scenarios.

The finite scalar enumeration covers:
  - ident: Any, exact(mE1), exact(mE2), exact(mBad);
  - identity observations: mE1, mE2, mBad;
  - SVN requirements and observations: V0, V1, V2;
  - TCB requirements: Both, OnlyGood, OnlyOutdated;
  - TCB observations: Good, Outdated, Revoked, Invalid;
  - attester contributions: NoAtt, Assign(P1), Assign(P2), Assign(P3);
  - actual attesters: P1, P2, P3.

For every enumerated scalar case, both an incorrect return value and an
unexpected reduction failure trigger a Wrong* event. All eight Wrong*
events were proved unreachable. Thus the checks do not pass merely because
a required successful operation is stuck.

The four raw false results are reachable POSITIVE witnesses:
  WildcardAndIdempotence, RedundantInputsEqual, OrderNormalization,
  CompatibleEntryAccepted.
In particular, RedundantInputsEqual uses three distinct Req contributions A,
B, and C and reaches an event with join(A,B) = join(join(A,B),C). This confirms
that the actual algebra permits different input sets to produce identical
normalized constraints. These traces are algebra witnesses, not attacks on
the SRAS protocol.

The composite negative checks prove unreachable the acceptance of the
specified measurement, signer, product, TCB and attester conflicts, and the
specified Invalid/Revoked and nonconforming entry-acceptance cases. They are 18
explicit composite scenarios, not an exhaustive Cartesian-product proof over
every possible full entry.

8. Ground-table specialization and its exact scope

The main-model generator uses a ground-table specialization of joinstar to
avoid the recorded generic symbolic expansion timeout. The diagnostic
models/join-specialization-regression.pv checks these actual generated tables
against jointcb and joinentry executed by ProVerif itself. It does not use the
Python merge_star implementation to calculate the expected result.

Read-only comparison confirmed all 11 labels and their actual input terms
in models/policy-catalog.json are present for each N=2/N=3 diagnostic:
  Compatible, Weak, StrongerSVN, ConflictMeasurement, ConflictSigner,
  ConflictProduct, ConflictTCB, ConflictAttester, RejectPeerTCB,
  NoAssignments, PermissiveRpeTCB.
Each N additionally has one HonestBase case. There are therefore 24 labelled
checks in total. HonestBase has the same normalized constraints as Compatible,
so it is not a twelfth independent adversarial policy profile.

WrongSpecializationN2 and WrongSpecializationN3 were both proved unreachable.
Each comparison checks both normalized output equality and agreement about
success versus failure, including conflict profiles that have no table rule.

This equivalence result applies to the current canonical fold domain only:
  N=2: the honest P1 base joined with each catalog contribution;
  N=3: honest P1 base joined with identical honest P2 constraints (still base),
       followed by each P3 catalog contribution.
It does not establish correctness of a joinstar call with arbitrary left
operands, arbitrary policies outside the catalog, arbitrary combinations of
several corrupted owners, or dynamically/inconsistently configured rosters.
The scalar/component algebra is broader than this table's supported domain;
the table is not presented as a complete implementation of that general join.

models/algebra.pvl, whose SHA-256 is:
